# 第一次使用：先聊通，再配媒体

这份教程配套 1.63.0-rc.21。先[下载完整源码包](https://github.com/cheems135/dsh-qq-bridge/archive/refs/heads/main.zip)，解压后保留整个目录；不要只下载一个 `index.js`。仓库提供了运行代码、工作流示例和说话参考音频，自己的 API Key 和 QQ 登录需要自行配置。

| 图片、视频、当前翻唱和备用翻唱请求 | [API 预设目录](../assets/api-presets) | 选择对应功能，导入后保存；填自己的 Key |

**贴吧参考不是整库聊天记录，也没有把聊天模型重新训练一遍。** 每组带原帖来源、短片段和原创迁移示例。插件会按语境选择，优先使用相处中学到的表达；不会每轮整包塞入提示词。不同模型、人设和已有记忆的效果仍会不同。

## 一、先安装宿主和插件

1. 电脑准备 DeepSeek Harness（DSH）；手机准备对应的 DSH Go 环境。本插件不是独立聊天客户端。
2. 用宿主版本提供的插件安装入口加载仓库根目录。`package.json` 和 `cordis.patch.yml` 必须保留，不要把示例配置当成完整用户配置覆盖进去。
3. 加载成功后打开「QQ 桥接」。页面看不到时先看宿主的插件加载错误，确认装的是完整目录。
4. 首次接入 QQ，按「账号与连接」页的 NapCat 启动和登录提示操作。手机须先启动本机引擎。

## 二、让普通聊天先通

1. 在「账号与连接」确认 QQ 登录和桥接连接分别成功。只在普通 QQ 窗口登录，不代表 NapCat 已接入插件。
2. 填自己的号主 QQ，配置允许互动的联系人和群。需要放开范围时在相应设置中调整，不要误把普通群成员当成号主。
3. 打开「连接与搭配」中的聊天功能卡，选择 API，填写自己的提供商、地址、模型和 Key。DeepSeek 是可用提供商之一，不是本插件的强制模型。
4. 选择人设，设置你们的称呼与关系；不要把 API 使用说明写进人设卡。
5. 从自己的 QQ 发一句普通闲聊，检查「收到消息 → 模型返回 → 发送队列 → QQ 回执」。先完成这一步，再测试图片和唱歌。

页面找不到时可用面板的功能搜索，搜索「账号」「学习」「语音」「唱歌」「本地」等名称。

## 三、使用已经准备好的媒体预设

详见[API 工作流与音色配置](api-workflows.md)。按顺序配置会更容易判断哪里出了问题：

1. 图片：导入 Qwen 双图编辑请求，确认提示词节点和图片输入。
2. 语音：按 Breeze 配置填入 Key 和自己能调用的音色 ID，先试听一句普通话。
3. 唱歌：导入当前翻唱流程，上传随包说话参考作为音色；不设置固定原曲和默认歌名。
4. 视频：选择已接入的 RunningHub 视频应用，先检查时长、画幅和人物参考图，再做一次短视频测试。

每个功能分别选 API 或本地；**API 的唱歌和语音在对应功能卡配置，不需要当成本地模型配置。** 纯手机不能启动 Windows 上的 ComfyUI。电脑使用本地聊天、同时使用 RunningHub 媒体时，需要显式开启对应云端能力。

## 四、打开学习，检查它是否真的被用到

在学习设置确认学习总开关开启。想继续积累自己的交流习惯，再打开相应的聊天学习或主动阅读选项。在「学习记录」查看：

- 已保存了什么，来源是什么；
- 本轮是否召回了该资料；
- 生成回复有没有使用，最后是否送达；
- 你的纠正是否写回，而不只是机器人说“我记住了”。

学习会提炼、检索和修正资料，不会自动修改模型权重。学习开启后也不保证每句话都玩梗；严肃话题、个人习惯和当时语境仍应优先。

## 五、更新与迁移

备份插件设置所显示的数据目录、记忆目录和素材目录，再替换程序文件。源码目录与运行数据不是一回事；换 QQ 或更新插件时不要清空记忆目录。更新后让宿主重载插件或后台，并在面板核对实际版本。刷新网页只能更新页面，不能保证后台已经加载新代码；无需为了更新插件反复退出 QQ。

这套预设不会自动覆盖已经保存的连接、人设、记忆或音色，也不会自动提交收费生成。导入后先核对，再保存，再试听或生成。
